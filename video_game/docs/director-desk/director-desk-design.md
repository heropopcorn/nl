# 「导演台」P0 历史设计与实现契约

> 此文档保留 P0 的背景与底层约束。导演台 V2 已实现章节、可摆放元素与整数层级、底图套索区域、多边形水域和多角色并行路线；当前操作规则以 [`usage.md`](usage.md) 和 [`README.md`](README.md) 为准。

状态：供 Cursor 开发的冻结设计稿  
目标工程：`video_game/`（Godot 4.7.2，桌面与 Web 同一套运行时 UI）  
本轮范围：设计与数据契约；不包含完整 Godot 实现  
数据示例：[`scene-schema.example.json`](scene-schema.example.json)

## 1. 一句话定位

「导演台」是一个在 Godot 运行时编排短镜头的工具：用户选背景、标出水流、安排角色路线、开关天气，然后预览演出并保存多个场景。

它不是 RPG，也不是完整关卡编辑器。P0 不做背包、任务、对话树、战斗、数值成长、TileMap、寻路烘焙、剧情分支、联网协作或云存档。现有 WASD 漫游是预览辅助手段，不是产品主循环。

## 2. 现状与改造原则

现有工程已经具备可复用基础：

- `runtime_editor.gd` 已有游玩/水域/路径模式和运行时 HUD。
- `village.gd` 已能替换背景、按贴图尺寸重建边界、从 mask 建水面碰撞。
- `scene_layout.gd` 已能把单场景 v1 数据保存到 `user://scene_layout.json`。
- `water_flow.gdshader` 目前只接受一个全局 `flow_dir`。
- `player.gd` 已能沿一条折线播放，但当前角色固定为 Player。

实现时采用渐进改造，不重写已有移动、镜头、文件选择与坐标换算。核心变化是：

1. 单场景编辑面板升级为三栏式导演台。
2. 单文件覆盖升级为多场景目录与索引。
3. 任意水面画刷升级为矩形水域对象，每个对象有独立方向。
4. 固定 Player 升级为可选择的角色实例与路线。
5. 增加轻量天气预览与统一播放控制。

所有用户数据只写 `user://`，绝不覆盖 `res://art/approved/`。Web 版本仍是纯静态 Godot 导出，不引入后端。

## 3. 用户与主流程

目标用户是需要快速摆出游戏画面并录制/观察演出的创作者，不要求懂 Godot 编辑器。

首次进入：

1. 打开导演台，左侧显示「示例村庄」；若不存在用户场景则自动从内置预设创建。
2. 点击「新建场景」。
3. 填写名称，并在「村庄预设」「空白画布」「上传背景」中选择一种背景来源。
4. 进入场景后，在右侧选择「水域」，拖拽矩形并为其设定流向。
5. 选择「角色」，添加角色，在画布点击路线点。
6. 打开「下雨」，点击底部「播放」预览；暂停后继续编辑。
7. 自动保存；返回场景列表后可再次进入。

高频返回流程：打开场景列表 → 选择场景 → 修改 → 播放/暂停 → 自动保存。

## 4. 信息架构与中文 HUD

桌面基准为 1280×720。HUD 分为四区：

| 区域 | 建议尺寸 | 内容 |
| --- | --- | --- |
| 顶栏 | 高 48 px | 「导演台」、当前场景名、保存状态、撤销/重做、帮助 |
| 左栏 | 宽 240 px | 搜索、场景列表、「新建场景」、场景菜单 |
| 中央画布 | 剩余区域 | 背景、角色、水域框、路线、选择框；支持缩放和平移 |
| 右栏 | 宽 320 px | 资源/水域/角色/天气四个页签及选中对象属性 |
| 底栏 | 高 64 px | 回到开头、播放/暂停、停止、循环、当前时间/状态 |

窄屏或 Web 宽度小于 900 px 时，左右栏变成互斥抽屉；中央画布不得被压到小于 480 px。P0 只保证鼠标和键盘，触控编辑为 P1。

### 4.1 中文文案基线

- 顶栏：`导演台`、`已保存`、`保存中…`、`保存失败`、`撤销`、`重做`。
- 左栏：`场景`、`搜索场景`、`新建场景`、`重命名`、`删除`、`复制`。
- 右栏页签：`场景`、`水域`、`角色`、`天气`。
- 场景页：`更换背景`、`显示内置道具`、`水面碰撞`、`恢复默认`。
- 水域页：`框选水域`、`流向`、`流速`、`启用碰撞`、`删除水域`。
- 角色页：`添加角色`、`角色类型`、`编辑路线`、`速度`、`循环`、`忽略碰撞`、`删除角色`。
- 天气页：`启用天气`、`天气效果：下雨`、`强度`。
- 底栏：`回到开头`、`播放`、`暂停`、`停止`、`循环预览`。

状态与错误必须用文字表达，不只靠颜色。删除、格式错误、尺寸超限等信息用中文；日志可保留英文。

### 4.2 模式与输入优先级

P0 模式为 `选择`、`框选水域`、`编辑路线`、`预览`，任一时刻只能有一个。

- 选择：左键选对象；右键/中键拖动画布；滚轮缩放。
- 框选水域：左键按下确定起点，拖动显示矩形，松开创建；`Esc` 取消本次框选。
- 编辑路线：左键追加路线点；拖动已有点调整；`Backspace` 删除末点；`Esc` 结束编辑。
- 预览：编辑手势锁定；`Space` 播放/暂停；`Esc` 停止并回到编辑前状态。
- 文本框或文件对话框聚焦时，全局快捷键不得触发。

编辑工具消费左键，镜头只消费右键/中键和滚轮，避免现有输入冲突。

## 5. P0 功能定义

### 5.1 场景列表与新建

场景列表按 `updated_at` 倒序，卡片显示名称、缩略图、更新时间。P0 提供新建、打开、重命名、删除；删除必须二次确认，且最后一个场景也允许删除，随后展示空状态。

新建弹窗字段：

- 场景名称：必填，去首尾空格，1–40 个 Unicode 字符。
- 背景来源：`村庄预设`、`空白画布`、`上传背景`三选一。
- 上传格式：PNG/JPEG/WebP；解码后最长边若大于 2048 px，等比缩至 2048；小于 320×180 时警告但允许。
- 文件大小：读取前最大 12 MiB；失败时不创建半成品场景。

`村庄预设`引用现有 `res://art/approved/chatgpt-terrain-ground-approved.png`；`空白画布`为 1152×864 的程序生成中性底色。上传图统一解码、转换并保存为场景目录内的 `background.png`，原文件名只作元数据展示。

### 5.2 背景与道具

更换背景沿用新建时的三种来源。更换后：

- 保持角色、路线、水域的 UV 坐标，因此布局按新图尺寸同比缩放。
- 重建地图边界和相机限制。
- 上传背景默认关闭内置切片道具，预设背景默认打开；用户可手动切换。
- 不自动识别水域，也不调用 `prepare_art.py` 的颜色启发式。

### 5.3 矩形水域与每区流向

水域是可选择对象，不再把画刷/polygon 当作导演台 P0 的主数据。一个水域由 UV 矩形、单位方向向量、流速、碰撞开关和启用状态组成。

交互：

1. 点击「框选水域」后在画布拖拽；小于 8×8 屏幕像素的框不创建。
2. 新框创建后自动选中，右侧出现八向按钮和可拖动方向箭头；默认方向为向下 `(0, 1)`。
3. 拖动中心移动矩形，拖动四角缩放；按住 `Shift` 可临时吸附 8 px 网格。
4. 相邻矩形允许共边，用于弯曲河流的分段；P0 禁止面积重叠。发生重叠时框显示红色，保存与播放按钮禁用，并给出「水域不能重叠」。
5. 每个区域单独实例化水面材质并设置 `flow_dir`，不能继续共用一个全局材质参数。
6. 碰撞使用对应矩形的 `RectangleShape2D`，只在创建、移动、缩放或切换碰撞时重建，不逐帧重建。

方向向量写入前归一化；零向量回退 `(0, 1)`。`flow_speed` 范围为 0–1.5。矩形 UV 坐标夹在 0–1，最小尺寸按背景像素换算为 8×8 px。

现有 mask 水面仍用于 v1 迁移的只读兼容显示，见第 8 节；新建/新编辑场景只写 `water_regions`。

### 5.4 指定角色与路线

P0 角色库至少提供两个可辨认选项，保证“指定角色”不是只有一个值的假选择：

| `character_id` | 中文名 | P0 资源策略 |
| --- | --- | --- |
| `farmer_placeholder` | 农夫 | 复用现有 `player_placeholder.png` |
| `farmer_blue_placeholder` | 蓝衣农夫 | 复用同一占位图并用固定蓝色 `modulate` 区分 |

它们是导演台功能占位角色，不代表最终美术。后续角色通过稳定的 `character_id` 注册，场景文件不直接引用任意系统路径；找不到 ID 时显示默认占位角色并给出警告，但不得改写原 ID。

P0 每个场景最多 1 个角色实例；数据结构使用数组，避免 P1 多角色时迁移格式。用户可选择角色类型、在画布点击出生点，并添加至少 2 个路线点。路线规则：

- 点位保存为背景左上角原点的 UV 坐标。
- `speed_px_per_sec` 范围 20–600，默认 210。
- 可选循环；非循环到终点停止。
- `collision_mode` 为 `ignore` 或 `world`，默认 `ignore`，与现有演出优先行为一致。
- 播放从 `start_uv` 开始，再依次到达 `route.points_uv`；若第一个路线点就是出生点，不得产生抖动。
- 少于 2 个路线点时允许保存，但播放前显示校验提示，角色保持出生点。

WASD 仅在停止状态作为人工走位预览；一旦开始路线播放，脚本驱动移动。WASD 若被用户按下，P0 不直接修改已保存路线，只停止预览并进入人工走位。

### 5.5 环境与天气

P0 天气是纯视觉演出开关，不影响角色速度、水流或碰撞。

- 主开关关闭时等价于晴朗，并暂停/隐藏粒子。
- 天气类型为 `rain`，右侧显示中文「下雨」；雨滴从屏幕上方出发，但只为降雨区域内的有效落点生成，不绘制没有终点的前景雨线。
- 强度 0–1，默认 0.6；统一驱动各降雨区域的落点密度和雨滴清晰度。
- 每个降雨区域保存 `points_uv`、`layer` 与 `splashes_enabled`。框线只限定内部落点的生成范围，不作为碰撞边界；落点在范围内均匀散布，每个落点对应一滴从屏幕顶部落下的雨，雨滴按落点高度行进相应距离后终止，水花与该雨滴同步并可逐区关闭。
- 雷电保存启用、强度和频率，使用不规则双段闪光与短暂分叉电光；仅在下雨启用时执行。
- 风保存启用、单位方向向量、0–1 风力与独立风速；风速控制值以指数曲线映射为 1×–20×，最低档等于旧版最高速度。细风丝采用多种弧形与 S 形轮廓，在固定位置平滑延伸、尾部渐隐，已有线身仅轻微摆动；少量风丝末端带短小自然卷，其余保持开放线形，并同步改变雨滴倾斜和落点方向。
- 停止预览后天气保持启用并继续显示，便于调参；只有主开关控制显隐。
- `time_of_day` 支持 `morning`、`noon`、`evening`、`night`；夜晚可用 `moonlight_enabled` 和 `moonlight_intensity` 控制冷色月光。

雪、雾和风仍属于后续迭代。

### 5.6 播放、暂停与停止

- 播放：从当前位置继续；首次播放或停止后播放，从场景开头开始。
- 暂停：冻结角色路径进度和导演台驱动的动态效果；再次播放续接。
- 停止：角色回到 `start_uv`，播放时间归零，天气配置不变。
- 回到开头：与停止相同，但不改变当前工具选择。
- 循环预览：路线结束后从开头重播；P0 单角色时以该角色路线结束为场景结束。

播放状态只属于运行时，不写入场景 JSON。

### 5.7 保存与恢复

所有修改先更新内存模型，300 ms 防抖后自动保存。顶栏必须显示 `保存中… / 已保存 / 保存失败`。切换场景或关闭窗口前立即 flush。若当前存在水域重叠等校验错误，内存中的红色预览保留但不落盘；切换场景时弹出「修正问题 / 放弃未保存修改」，不能静默丢弃。

每次保存流程：校验 → 写 `scene.json.tmp` → 成功后替换 `scene.json` → 更新索引。保留一份 `scene.json.bak`；启动解析失败时尝试备份，并明确提示用户。P0 同时提供 `Ctrl/Cmd+S` 立即保存。

## 6. 数据模型与文件契约

### 6.1 目录结构

```text
user://director_desk/
├── index.json
└── scenes/
    └── scn_7f3a2c91/
        ├── scene.json
        ├── scene.json.bak
        ├── background.png        # 仅 uploaded 背景存在
        ├── thumbnail.png         # 自动生成，可丢弃重建
        └── legacy_water_mask.png # 仅旧版迁移场景可能存在
```

`scene_id` 在创建时生成，格式 `scn_` 加 8–32 位小写十六进制；之后不随重命名改变。用户可见名称不用于路径。任何相对资源路径解析后必须仍位于本场景目录内，拒绝绝对路径、`..`、URL 和 `res://` 注入。

### 6.2 `index.json`

```json
{
  "schema_version": 1,
  "active_scene_id": "scn_7f3a2c91",
  "scenes": [
    {
      "id": "scn_7f3a2c91",
      "name": "雨中的村口",
      "updated_at": "2026-09-17T12:34:56Z",
      "thumbnail": "scenes/scn_7f3a2c91/thumbnail.png"
    }
  ]
}
```

索引只是可重建缓存。启动时若索引损坏，扫描 `scenes/*/scene.json` 重建；单个场景损坏不应阻止其他场景打开。

### 6.3 `scene.json`

完整实例见 `scene-schema.example.json`。规范如下：

| 字段 | 必填 | P0 规则 |
| --- | --- | --- |
| `schema_version` | 是 | 整数 `2` |
| `scene_id` | 是 | 与目录名相同且创建后不可变 |
| `name` | 是 | 1–40 字符 |
| `created_at`, `updated_at` | 是 | UTC RFC 3339 字符串 |
| `background` | 是 | `preset`、`blank` 或 `uploaded`；像素尺寸必须为正整数 |
| `coordinate_space` | 是 | 固定为左上原点、normalized UV；用于拒绝未知坐标解释 |
| `editor` | 是 | 内置道具、水面碰撞总开关、网格设置 |
| `water_regions` | 是 | 数组；P0 最多 64 个，不得重叠 |
| `rain_regions` | 是 | 数组；最多 64 个世界空间多边形，逐区保存水花开关和层级 |
| `actors` | 是 | 数组；P0 最多 1 个，ID 在场景内唯一 |
| `weather` | 是 | 雨、昼夜、月光、雷电以及风向/风力参数 |
| `camera` | 否 | P1；P0 读取后保留但不执行 |
| `legacy_water` | 否 | 仅 v1 迁移产生，只读兼容 |

共同规则：

- 所有 UV 数字有限且位于 `[0, 1]`；矩形是 `[x, y, width, height]`。
- 未知字段必须原样保留，便于前后版本兼容；未知枚举值不可执行，应提示并使用安全默认值。
- 所有对象 ID 在所属数组内唯一，采用 `water_…`、`actor_…` 前缀。
- JSON 最大 1 MiB、数组长度设上限，解析失败不得执行部分数据。
- 浮点保存到最多 6 位小数；不要依赖 JSON 字段顺序。
- `background.file` 仅在 `source = uploaded` 时需要；预设依赖 `preset_id`，空白依赖 `fill_color`。
- `editor.water_collision_enabled` 是全局总开关，并与每个水域的 `collision_enabled` 取 AND。

### 6.4 坐标换算

背景纹理居中放在世界原点，文件 UV 以左上为 `(0, 0)`、右下为 `(1, 1)`：

```text
world = -texture_size / 2 + uv * texture_size
uv    = clamp((world + texture_size / 2) / texture_size, 0, 1)
```

矩形世界位置与尺寸由 `rect_uv` 同样换算。HUD、相机 offset 和窗口尺寸绝不能写入 UV。

## 7. P0 / P1 / 明确不做

### P0：首个可交付版本

- 中文三栏 HUD 和四种互斥模式。
- 多场景列表；新建、打开、重命名、删除。
- 预设/空白/上传背景与 2048 px 限制。
- 矩形水域，每区方向、速度、碰撞；相邻可接、不可重叠。
- 单角色选择、出生点、折线路线、速度/循环/碰撞模式。
- 下雨开关与强度。
- 播放/暂停/停止/回到开头。
- 自动保存、保存状态、单步撤销/重做栈（见增补能力）。
- v1 数据一次性迁移、损坏文件恢复、基础校验与 headless 测试。

### P1：P0 稳定后

- 场景复制、导出/导入场景包。
- 多角色与时间轴对齐（延迟、到点停留）。
- 镜头关键点与缩放预设。
- 雪、雾、风、昼夜。
- 道具逐个显隐与摆放（不是任意资源关卡编辑）。
- 触控编辑、框选多对象、更多快捷键。

### 本产品不做

- 独立 React/HTML 编辑器、云端项目、账号、协同编辑。
- RPG 系统、对话树、战斗、任务、背包或经济系统。
- TileMap/完整关卡编辑器、任意脚本、任意本地路径资源引用。
- 流体模拟、Flow Map 编辑器、自动河流识别、NavMesh 自动寻路。
- 视频录制/编码和自动发布；用户可用现有录屏工具记录预览。
- 默认写回 `res://`、覆盖 approved 美术或修改 `codex/asset-gen/`。

## 8. v1 兼容与迁移

当 `user://director_desk/index.json` 不存在、但 `user://scene_layout.json` 存在时执行一次迁移：

1. 创建一个 v2 场景，名称为「从旧版导入」。
2. `ground` 为空则使用 `village_default`；否则复制 `custom_ground.png` 到新目录。
3. 把 `path_uv` 转成一个 `farmer_placeholder` 角色的路线；出生点取首点，无点则 `(0.42, 0.42)`。
4. `hide_baked_props` 转为 `editor.show_baked_props` 的反值。
5. 旧 `water_mask.png` 无法无损转成矩形，复制为 `legacy_water_mask.png`，以旧全局 `water_flow_dir` 只读渲染；HUD 显示「旧版水域：请重新框选」。
6. 原文件不删除、不覆盖。索引写入成功后，后续启动不重复迁移。

P0 可删除旧版水域，但不能继续画刷编辑它。这样既保留已有作品，又不污染新矩形契约。

## 10. 实现建议与文件边界

建议拆分职责，避免继续把所有逻辑塞进 `runtime_editor.gd` 与 `village.gd`：

| 建议组件 | 单一职责 |
| --- | --- |
| `director_desk.gd` | HUD 组装、模式机、选中对象、命令派发 |
| `scene_repository.gd` | index/scene CRUD、原子保存、备份、v1 迁移 |
| `director_scene_model.gd` | v2 解析、校验、未知字段保留、序列化 |
| `water_region_controller.gd` | 矩形 gizmo、独立材质、碰撞节点 |
| `actor_controller.gd` | 角色注册、路线编辑与播放适配 |
| `weather_controller.gd` | 屏幕空间天气效果 |
| `preview_controller.gd` | 播放状态、统一时钟、停止复位 |

可继续复用 `world_to_uv` / `uv_to_world`、背景加载与尺寸限制、相机平移缩放、现有 Player 路径移动。`water_flow.gdshader` 可复用，但每个水域必须使用独立 `ShaderMaterial` 实例，避免改一个方向导致全部区域变化。

运行时节点建议：

```text
Village
├── World
│   ├── Terrain
│   ├── WaterRegions
│   ├── Props
│   ├── Actors
│   └── DirectorGizmos
├── WeatherCanvas
└── HUD
    └── DirectorDesk
```

## 12. 风险与规避

| 风险 | 影响 | 规避/验收观察 |
| --- | --- | --- |
| 多区域仍共享材质 | 修改一个流向会改变全部水域 | 每区域 duplicate material；自动测试比较参数 |
| UV 与中心坐标混淆 | 换背景后水域/路线偏移 | 只在 model boundary 转换；用四角测试 |
| 水域重叠产生双重透明 | 接缝明显、方向不确定 | P0 禁止面积重叠，允许共边 |
| Web `user://` 非云存储 | 换设备或清站点数据会丢失 | 明示本机保存；P1 提供导出包 |
| 上传超大图 | Web 内存峰值或卡死 | 先查字节上限，解码后缩到 2048；错误不建场景 |
| 高频落盘和碰撞重建 | 拖拽卡顿 | 拖拽时只预览，松手提交、重建、延迟保存 |
| 角色撞水后停住 | 预览与编排不一致 | 默认 `ignore`；选择 `world` 时给路线碰撞提示 |
| 中文字体缺字 | HUD 方块字 | 使用 Godot 可覆盖 CJK 的系统/内置字体并在 Web 验证 |
| v1 mask 不能矩形化 | 老作品水面丢失 | 只读 legacy overlay，明确提示重画 |
| P1 字段被 P0 丢弃 | 后续版本回存损坏数据 | 未知字段 round-trip 保留 |

## 13. 验收标准

### 场景与持久化

- Given 首次启动无用户数据，When 打开导演台，Then 能看到示例场景或明确空状态，并能从两种预设或上传图创建场景。
- Given 已有两个场景，When 重命名、切换并刷新/重启，Then 名称、活动场景和各自内容保持，数据互不串场。
- Given 删除场景，When 未确认，Then 不删除；确认后只删除该 ID 目录并更新列表。
- Given 写入中断产生损坏 JSON，When 再启动，Then 尝试 `.bak`，其余场景仍可打开。

### 背景与水域

- Given 上传 4000×2000 图片，When 创建场景，Then 内部图为 2048×1024，边界和相机与新尺寸一致。
- Given 创建两个相邻水域并设为相反方向，When 播放，Then 两区纹理明显向各自方向运动，修改 A 不改变 B。
- Given 两个矩形发生面积重叠，When 松手，Then 显示中文错误且不能保存/播放；共边不报错。
- Given 水域碰撞总开关关闭，When 角色经过，Then 所有水域均不阻挡；重新打开后仅区域开关为开的水域阻挡。

### 角色、天气与预览

- Given 选择角色并创建 3 点路线，When 播放/暂停/继续，Then 角色按设定速度移动，暂停位置不跳变，停止回出生点。
- Given 角色库已打开，When 在农夫与蓝衣农夫之间切换，Then 画布角色外观和保存的 `character_id` 同步变化。
- Given 路线循环关闭，When 抵达终点，Then 播放结束并停在终点；停止后回出生点。
- Given 启用下雨、框定屋顶与地面并调整强度，When 预览和移动镜头，Then 框内均匀分布的每个落点都有一滴从屏幕上方落下的对应雨滴，不出现无终点的前景雨线；上下落点分别产生不同下落行程，开启水花时命中同步飞溅，关闭水花时雨滴仍在隐藏落点终止，且不改变角色速度。
- Given 预览进行中，When 尝试拖水域或路线点，Then 不修改数据；停止后可继续编辑。

### 编辑质量与兼容

- Given 创建、移动、删除水域，When 连续撤销/重做，Then 至少 50 步内模型、画面和保存结果一致。
- Given 存在 v1 `scene_layout.json`，When 首次升级，Then 背景、路线、道具显隐迁移，旧 mask 可见且旧文件仍在。
- Given 运行 `godot --headless --path . --import --quit` 与扩展后的 `--selftest`，Then 均退出 0。
- Given 导出 Web 并刷新页面，Then 当前浏览器中的多场景仍从 `user://`/IndexedDB 恢复；界面不声称已经云同步。

## 14. P0 完成定义

只有在上述 P0 checklist、验收项和桌面/Web 两端关键流程都通过后，才能称为「导演台 P0」。视觉润色可以后补，但以下不可降级：多场景隔离、矩形水域独立流向、角色路线、天气开关、中文可理解状态、保存恢复与旧数据不丢。
