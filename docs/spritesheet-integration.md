# 序列帧制作与自定义分类

入口：左侧资源库 → 自定义资源 → 制作序列帧。也可从“更多资源”大窗口打开。

1. 在资源库或制作窗口输入新分类名称，点击“新增分类”。名称不可为空、不可重复，最多 100 个分类。
2. 选择或拖入本地视频，按 FPS 或时间间隔抽帧，最多 120 帧。视频本地解码，不上传外部服务。
3. 点击帧可查看，勾选启用、拖动排序或前移／后移；按需对选中帧或所有启用帧去除底色。
4. 设置列数、帧内边距、帧间距、格宽高和对齐方式，合成并预览图集。变更帧或合成参数后必须重新合成，避免保存过时结果。
5. 选择自定义分类、设置播放 FPS，保存到自定义资源。PNG／JSON 也可单独下载。
6. 关闭制作窗口，在对应自定义分类点击资源放入 2D 场景。序列帧自动播放，不需要场景时间轴。

本地工作模式（`npm run work`）中，分类、帧矩形、FPS 和制作草稿写入工作目录的 `project.json`；视频、逐帧 PNG、图集写入 `media/`。文件按内容哈希命名，项目中只保存相对路径，不依赖原视频在电脑上的绝对路径。旧项目没有分类／草稿字段时自动使用空列表。普通图片也可上传到新分类（作为可放置的图片道具）。原有背景／音频／模型等类型入口继续保留。

在线预览仍只是演示：分类和成品存浏览器数据库，原视频和制作草稿不持久化到磁盘，不接 Supabase。

限制：视频最多 80MB；最多 50 份制作草稿、每份最多 120 帧；图集单边最多 8192，总像素最多 16,777,216；最多 200 项自定义资源。本地素材上传服务单文件上限 512MB，但抽帧仍使用上述 80MB 限制；在线演示单 PNG 上限 20MB、资源 JSON 总量上限 100MB。浏览器需能解码相应视频格式，保存 MOV/MKV 不代表浏览器支持它们的编码。背景去除使用边缘颜色泛洪，不是 AI 抠图；复杂背景需要其他工具处理。透明边缘裁切默认关闭，避免逐帧重对齐引起抖动。

## 本地制作与跨电脑同步

- “保存制作草稿到磁盘”：可在选好视频后、选帧中途或合成后使用，保存原视频、全部帧（包括未启用帧）、帧顺序／时间点、去底后的像素、抽帧／合成参数及已有合成图。无需先创建资源分类。
- “保存到自定义分类”：本地模式下同时保存制作草稿和最终资源；成功提示只在实际磁盘写入完成后显示。
- “已有制作草稿 → 打开制作草稿”：恢复原视频和逐帧文件，不需要重新选择视频或重新抽帧，去底结果不会因重新解码而改变。
- 修改后需要再次保存；未保存时关闭／刷新会提醒。保存失败时不要刷新，可在原窗口重试；版本冲突仍禁止覆盖。
- “移除制作草稿”只移除项目记录，已保存的自定义资源不受影响，文件不会立即删除。项目备份和仍被引用的媒体受清理保护。
- 原视频、处理帧与输出随 `project.json` 和 `media/` 一起提交 Git。另一台电脑拉取后，用 `npm run work` 打开同一工作目录即可继续。不要在编辑器运行时拉取或切换分支。
- `.nlpack` 项目包包含完整制作草稿及其全部媒体，并验证内容哈希。含视频制作草稿的项目不再导出旧式内嵌 JSON，请使用“本地文件 → 导出项目包”或同步整个工作目录。

未启用 Git LFS、未自动执行 Git 提交／推送、未加入 Supabase。未来云端视频确认可作为独立功能接入，不改变此本地主工作流。

## 来源与适配

核心算法移植自 `/workspace/imageHandle` 远端 `main`，提交 `d87aaa2`（序列帧实现来自 `eae4cca`）。源仓库工作区保持在原提交，未切换或修改。

- `packages/spritesheet/spriteFrames.ts`：抽帧参数、时间采样、帧排序。
- `spriteExtract.ts`：浏览器视频抽帧；增加取消清理和内存限制。
- `spriteCutout.ts` / `matting.ts`：边缘泛洪去底与裁切；调整 URL 生命周期为调用方管理。
- `spritePack.ts`：图集排版及 PNG／JSON；增加图集尺寸上限。
- 制作面板重新适配本项目布局；保存取代原站云端存储。
- `packages/core/sprite-frame.ts`：按实际帧矩形播放，支持帧间距与未填满末行；旧资源继续按行列切分。

验证：单元测试覆盖时间采样、图集排版、旧项目兼容、分类引用、帧边界及尺寸限制；浏览器测试使用真实 WebM 抽帧并验证去底、排序、保存、导出、自动播放和刷新恢复。
