# 在线预览与本地工作模式

一套编辑器，两种存储实现。无需数据库或 OSS；完整默认素材暂时继续提交 GitHub。

## 在线预览／功能开发

```sh
npm ci
npm run dev
```

`npm run build` 默认生成 `preview/demo`。Vercel 原构建脚本明确使用此配置，继续只发布静态文件，保留现有登录 middleware。不会启动或请求本地磁盘 API。

- `apps/director-web/scripts/demo-assets.json` 指定精简素材、时节与分辨率。
- 按清单复制到 `.generated/preview-demo`；测试用 `.generated/preview-full`，本地用 `.generated/local-full`。不同模式不会清理彼此的资源，也不删除 Git 中的源图。
- 输出分别为 `dist-preview`、`dist-preview-full`（完整资源测试预览）、`dist-local`；Vercel 只复制 `dist-preview`。不再使用旧的共享 `dist`／`public/art`。
- 生成 `runtime.json`，资源库按实际发布内容过滤；未发布时节不可选择。
- 图片、场景、天气、套索、资源分类、浏览器序列帧制作和 PNG 输出可正常预览。
- 项目保存在当前浏览器 IndexedDB／localStorage，没有云端同步。用户需导出项目留存。
- 默认不提供 `/api/workspace`、`/api/export`。没有服务时不会尝试磁盘保存。
- 完整项目如果引用未打包的默认资源，会提示切换本地工作模式；不会擅自替换原资源。

当前精简清单发布 16 张图，完整清单发布 88 张图。资源仍存在 Git 历史，仓库克隆大小不会随部署包一起缩小。

## 本地实际工作

需要 Node.js 20.19+ 和 npm。首次安装需网络；完整源码与素材下载到本地后可运行。

```sh
npm ci
npm run work
```

Windows 示例（路径有空格必须加引号）：

```powershell
npm run work -- --workspace "projects/我的作品"
```

不传 `--workspace` 或 `NL_WORKSPACE` 时，使用仓库内的 `projects/default`。相对路径以仓库根目录为基准；命令行参数优先于环境变量。目录不存在时自动创建。仓库内只允许 `projects/<作品名称>`，禁止使用仓库根、源码和构建目录；显式指定的外置目录仍兼容旧版。

默认素材原本就在 `assets/` 和 `video_game/art/`，路径不变。新增自定义素材写入所选作品的 `media/`，项目内容写入 `project.json`，两者都可提交 Git。`projects/.gitignore` 排除工作锁、自动备份、回收区、导出目录及临时文件。本次尚未启用 Git LFS。

如果旧版默认目录 `~/YuanliProjects/default/project.json` 存在，而仓库内还没有作品，启动会提示迁移，避免误以为旧数据消失。先指定旧目录导出项目包，再显式执行 `npm run work -- --workspace projects/default` 导入。旧目录不自动删除或覆盖。

命令会构建 `local/full`，然后启动 `http://127.0.0.1:4173`；沿用现有登录账号配置。不要将这个本地文件服务暴露到公网。`PORT` 可更改端口，`FFMPEG_PATH` 可指定 FFmpeg 可执行文件。

也可先完整构建，再使用 `NL_MODE=local npm start` 启动已有 `dist-local` 和仓库内默认作品，避免重复构建。设置 `NL_WORKSPACE` 可选择其他作品。Windows PowerShell 可先用 `$env:NL_MODE="local"`、`$env:NL_WORKSPACE="projects/我的作品"` 设置变量。默认 `npm start` 运行精简预览；服务器发现模式不匹配会拒绝启动。

```text
projects/default/
├── project.json          项目、场景、分类、视频制作草稿与相对素材引用
├── media/                按内容哈希命名的素材、原视频、处理帧及图集
├── backups/              历史项目 JSON，不重复存素材
├── exports/              预留输出目录
├── .trash/               经确认清理后的可恢复批次
└── .workspace.lock       工作进程锁，正常退出后自动移除
```

### 保存与安全

- 新上传资源直接存入 `media/`，项目 JSON 不嵌入 Base64；相同内容去重。
- 文档用临时文件＋同步写入＋重命名保存。素材先落盘，再保存引用。
- 自动备份至少间隔一分钟；“本机备份”可手动创建／恢复。界面显示最近 50 份，磁盘旧备份不自动删除。
- 同一目录只允许一个工作服务；多个浏览器窗口使用版本校验。普通保存失败可通过“重试保存”或 Ctrl+S 重试，不会绕过版本检查。冲突需要先导出修改，再重新打开磁盘版本处理，不能直接覆盖。
- “未保存”状态独立于请求是否结束：失败后关闭页面仍会警告。恢复草稿按工作目录／窗口隔离存入浏览器 IndexedDB；同一窗口刷新时询问是否恢复，其他草稿可从右下角“本地文件”入口恢复。草稿恢复仍检查原始版本，不能覆盖其他窗口的新内容。草稿存储失败会额外警告；浏览器草稿不是外部备份。
- 登录过期时 API 返回 401，不再重定向 HTML。使用提示中的“在新窗口登录”，完成后回到原编辑窗口重试，无需刷新丢弃修改。导出会校验响应类型、项目格式和 JSON 大小。
- 自动保存合并连续操作并短暂防抖，减少反复写入完整项目。
- 损坏项目不会被示例项目自动覆盖。请从 `backups/` 恢复 `project.json`，保留损坏文件供排查。
- 正常停止用 Ctrl+C。端口被占用等启动失败会自动释放已取得的锁。异常断电留下锁时，可运行 `npm run work -- --unlock --workspace "项目目录"`；只有锁属于本机且原进程确实不存在时才会解除，进程仍在运行或无法安全判断时拒绝。解除后再正常启动。
- 素材 API 校验本机 Host，写入校验同源与随机令牌；路径限定在工作目录，拒绝符号链接逃逸；API 仍需登录。
- 删除资源只是删除项目引用，不立即删除二进制文件，以免破坏历史备份。

### 视频抽帧制作

进入“自定义资源 → 制作序列帧”，选择或拖入本地视频，抽帧、去底、排序后可保存到自定义分类。本地保存成品时也保留制作草稿；中途可点击“保存制作草稿到磁盘”，无需先合成或选择分类。

草稿包含原视频、全部处理帧（包括未启用帧）、选帧顺序与时间点、抽帧／合成参数和已有图集。重新打开编辑器，通过“已有制作草稿 → 打开制作草稿”继续，不依赖原文件路径或浏览器缓存。修改后需再次保存，未保存时离开会提醒。最多 50 份草稿，可移除记录；素材仍受当前项目及历史备份引用保护，不会立即删除。

制作记录位于 `project.json` 的 `spriteDrafts`，所有二进制文件位于 `media/`，可以通过 Git 或项目包完整转移。详细操作见 [序列帧制作说明](spritesheet-integration.md)。

### 导入与迁移

线上浏览器和本地项目存储隔离，不会把浏览器草稿自动写进磁盘项目。

1. 在原在线预览页面使用“导出项目”。
2. 在本地工作模式使用“打开项目”，选择导出的 JSON。
3. 确认替换当前工作目录项目；会先备份旧项目，并将嵌入素材拆成独立文件。

“导出项目”保留兼容的可携带 JSON，含视频制作草稿或导出超过导入上限时会提示使用项目包，避免导出后无法重新导入。

本地右下角 **本地文件 → 导出项目包／导入项目包** 使用 `.nlpack`：标准未压缩 USTAR，包含 `project.json` 和去重后的自定义素材二进制文件，不使用 Base64。服务端流式打包／解包；支持浏览器文件写入接口时直接流式写入用户选择的位置。其他浏览器使用下载方式且限制 256MB，超出后提示改用支持文件写入的浏览器或复制目录。

- 单个素材上限 512MB，项目包上限 8GB，项目描述上限 32MB。超限项目请复制整个工作目录；不会生成超出自身导入限制的包。
- 导入校验文件名、路径、项目结构、条目完整性和素材 SHA-256；拒绝重复路径、链接、额外条目、损坏／截断文件。通过验证后备份旧项目，最后原子替换项目描述。失败不会以半个项目替换当前作品。
- 项目包包含当前项目自定义素材、制作草稿、原视频、处理帧及已有图集，不包含历史备份、回收区或内置素材库；完整默认资源仍依赖软件附带的素材库。完整迁移请复制软件及工作目录。

### 磁盘管理与外部备份

右下角 **本地文件 → 检查磁盘占用** 显示素材、备份大小和清理候选清单，保留备份份数可设为 1–500（默认 50）。没有自动删除策略。

只有当前项目及保留备份都未引用、且写入超过 24 小时的素材会成为候选；损坏备份会阻止清理，需要先人工排查。执行前重新检查项目及备份版本，清单变化则要求重新预览。

确认后先移动到 `.trash` 回收批次，**这一步不释放磁盘空间**。可恢复批次；永久删除需要单独确认，删除后不可恢复。清理前请保存项目；旧撤销记录若引用已清理素材，需要先恢复对应批次。

仓库内作品的 `project.json` 和 `media/` 可与软件一起提交到 GitHub，但**保存到磁盘不等于已经提交／推送**。换设备前等待保存完成、停止本地服务，再提交并推送；另一台设备先拉取再启动。不要在运行中的工作区拉取、切换分支或自动合并项目 JSON。若仓库公开，提交的素材和作品也会公开。

显式选择的外置作品仍不属于本仓库。自动备份、回收区不提交 Git，也不能防止整块硬盘故障；请保留独立备份。大文件提交前需另行配置 LFS。线上构建只复制生成的静态资源，不包含 `projects/`。

### 本阶段边界

- 一个工作目录对应一个项目文档（文档仍包含多个章节／场景）；切换目录通过停止服务并换启动参数完成，暂未增加系统文件夹选择器。
- 本地素材上传单文件上限 512MB，线上仍为 20MB；图片尺寸及浏览器抽帧限制保持原样（视频最多 80MB、每次最多 120 帧）。保存制作草稿／成品时保留原视频；尚未增加可直接放入场景的视频元素或后台大视频处理。
- Supabase 云端视频确认工具留待独立开发；当前没有数据库／云存储依赖，不启用 Git LFS，也不会自动提交或推送。
- 本地启用已有 FFmpeg 导出 API；时间轴与 MP4 导出界面仍按此前要求暂停，没有重新引入时间轴。PNG／项目导出仍使用浏览器下载位置，`exports/` 是预留目录。
- 尚未做桌面安装包。仓库内作品会随 Git 版本变化，应在停止编辑后再更新或切换版本；备份到第二块磁盘仍需用户安排。

## 测试

```sh
npm test
npm run prepare:server
node --test tests/workspace-service.test.mjs tests/asset-profiles.test.mjs
node --test tests/workspace-package.test.mjs
node --test tests/workspace-spritesheet.test.mjs
TEST_PORT=5184 npx playwright test
```

完整浏览器回归自动使用 full 素材，并显式启用测试专用导出 API。两种实际构建另有独立测试：

```sh
npm run build
node --test tests/preview-mode.test.mjs
NL_MODE=local NL_ASSET_PROFILE=full npm run build
node --test tests/local-work.test.mjs
node --test tests/workspace-startup.test.mjs
```

这些环境变量写法适用于 POSIX shell；Windows 日常使用 `npm run work` 无需手动设置变量。测试会创建并清理独立临时工作目录，不修改真实作品。
