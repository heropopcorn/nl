# 仓库内的作品与自定义素材

`npm run work` 默认打开 `projects/default/`。其他作品可用 `npm run work -- --workspace projects/作品名称` 打开。

每个作品目录包括：

```text
default/
├── project.json       场景、资源分类、视频制作草稿及相对素材引用（提交 Git）
├── media/             图片、音频、模型、原视频、处理帧及图集（提交 Git）
├── backups/           本机历史备份（不提交）
├── exports/           导出产物（不提交）
├── .trash/            清理回收区（不提交）
└── .workspace.lock    本机工作锁（不提交）
```

- 内置素材继续使用仓库中的 `assets/` 和 `video_game/art/`，无需重复搬动。
- 自定义素材由程序自动写入 `media/`，按内容哈希命名；不要手动重命名或分散移动。
- 视频抽帧在“自定义资源 → 制作序列帧”中进行。点击“保存制作草稿到磁盘”保留原视频、逐帧处理结果和选帧参数；“保存到自定义分类”同时保存草稿与成品。下次从“已有制作草稿”继续编辑。未保存的制作修改仍仅在内存中。
- 制作草稿也包含在 `.nlpack` 项目包中，素材清理会保护当前草稿和保留备份引用的视频／帧文件。
- 换设备前等待保存完成、停止本地服务，再提交并推送项目 JSON 和素材。另一台设备先拉取，再启动编辑器。不要在运行中的工作区执行切换分支或拉取。
- 同步依赖 Git 提交／推送，不会因“保存到磁盘”自动上传。此变更没有安装或启用 Git LFS，大文件提交前仍需配置 LFS。
- 自动备份、回收区不会随 Git 同步；重要作品仍应另做独立备份。仓库若为公开仓库，提交的作品和素材也会公开。
- 线上预览构建不会复制 `projects/`；这里只供本地工作使用。

## 旧作品迁入

旧版外置目录不会自动删除或覆盖。在旧目录运行编辑器并导出 `.nlpack`，然后用 `npm run work -- --workspace projects/default` 打开仓库内作品，导入项目包即可。项目包会自动恢复素材路径，不需要逐个复制文件。

浏览器模式中的旧作品仍需先导出 JSON，再在本地工作模式中导入。
