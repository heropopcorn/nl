# 待确认资源入口

将需要人工确认的图片、视频、动图放入 `inbox/`（支持子目录），随 Git 推送。启用云端确认后，构建只发布未标记的文件。

这里只扫描 `resource-review/inbox/`，不会自动扫描或发布 `assets/`、`video_game/art/`、参考图／参考视频等其他目录。“当前没有未标记素材”只表示本次部署的待确认批次为空，不表示整个仓库没有素材或所有素材都已确认。应先明确要确认的批次，再将对应文件放入此入口；不要直接把全部参考素材加入。

登录 nl 后点击顶部“资源确认”。bot 执行 `npm run review:sync` 后，在本目录的 `decisions.json` 读取可用／不可用／未确认结果和对应本地路径。

- `inbox/` 原始文件提交 Git；确认结果以云端数据库为准。
- `decisions.json` 是同步报告，不提交 Git；同步失败不得使用旧报告执行整理。
- 不可用素材不会自动删除或移动；由 bot 核对后按明确要求归档。
- 公开仓库中的素材也是公开的。新部署移除文件不会清除旧部署或 Git 历史。

启用确认并成功扫描后，构建的 `resource-review/manifest.json` 会包含可选的 `scan` 统计：

- `source` 固定为 `resource-review/inbox/`；不包含本机绝对路径或未发布文件的路径。
- `files` 是入口内支持的媒体文件数（包含内容相同的副本）；`uniqueAssets` 按内容哈希去重。
- `images`／`animations`／`videos` 是去重后的静态图片／动图／视频数量，三者之和等于 `uniqueAssets`。
- `pending` 是本次发布的未确认素材数，`reviewed` 是入口内已标记可用或不可用的素材数，两者之和等于 `uniqueAssets`。

构建日志会区分“入口没有媒体文件”和“入口中的素材已全部标记”。未启用确认的构建不扫描入口，也不生成 `scan`；旧部署也可能没有此字段，不能据此推断入口为空。每个文件最多 50MB，每次发布最多 500 项、合计 200MB；超出时需要分批，构建不会自动截断或删除原件。

首次启用、环境变量、权限及详细流程见 [资源确认说明](../docs/resource-review.md)。
