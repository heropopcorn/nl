# 「元力 / 游戏视频」双视角可行性评估

> 评估对象：在现有俯视村庄方向之外，是否增加 2D 横版侧视等第二种视角。  
> 依据：小红书参考合订 PDF 及五个分册、现有锁定美术与世界设定、项目进度记录、童年男女主 V1 设定板、已批准地形图与资产表。  
> 本文讨论的是“用游戏场景制作视频”的演出系统，不是要把项目扩成一款必须全程自由游玩的双视角游戏。

## 一、结论

**适合采用两种视角，但应采用“主视角 + 受控副视角”的 1+1 结构，不适合现在就建设两套平权、全覆盖的内容管线。**

- **主视角继续使用当前已锁定方向**：严格正交、无近大远小的俯视地面，叠加固定角度的斜俯视建筑、树木和道具，形成温暖手绘的俯视 / 伪 2.5D 游戏舞台。
- **副视角建议使用正交横版侧视**：水平地面线、无纵深缩放，以少量远中近景视差营造空间；仅用于最能发挥其优势的线性旅途、情绪段落和少数侧面表演。
- **不建议把“纯 90° 俯视”和“斜俯视 / 2.5D”拆成两个独立视角**。现有规范中的“俯视地面 + 斜俯视资产”本来就是同一个组合式主视角。如果再把二者分成两套镜头，叙事增益很小，却会增加资产角度与角色方向的混乱。
- **不建议立刻全面启用横版**。当前项目最关键的未关闭风险仍是同一角色在正、背、侧、动作和年龄变化中的稳定复用。双视角会直接放大这个风险。正确顺序是：先让一个主角通过“俯视四方向 + 横版侧面”的最小生产测试，再决定副视角占比。

建议最终成片的初始配比为：**俯视主视角约 75%～85%，横版副视角约 15%～25%**。这个比例是生产规划建议，不是硬性剪辑规则。前几集宜更保守，先让观众建立村庄和人物的空间认知。

一句话概括：**可以双视角，但横版应像一种有明确语义的镜头语言，而不是另一套随时切换的游戏模式。**

## 二、为什么这个项目确实能从双视角获益

### 1. 两种视角解决的是不同叙事问题

| 视角 | 最强能力 | 对本项目的价值 |
|---|---|---|
| 俯视 / 正交斜俯视主视角 | 交代空间、路线、群像、多人站位、日常循环 | 最适合村庄生活、学堂、农田、课堂活动、多人入场离场和“世界是可以行走的地图”这一核心观感 |
| 横版侧视副视角 | 表现方向明确的移动、地平线、天气、沿途风景、两人并行和情绪留白 | 最适合上学路、跨村旅途、河岸同行、马车 / 飞行载具经过、离乡和抵达新城市等成长节点 |

「元力」目前锁定的是正常的教学成长线：入学、成长、认识世界、最终离乡升学。它不是高频战斗或灾难解谜故事。因此，双视角的真正价值不是做平台跳跃，而是把两种尺度区分开：

- 俯视负责“人在一个社会和场所里生活”；
- 横版负责“人正在穿过世界，并发生阶段变化”。

这与故事从东南小村庄逐渐走向区域城市和高等学府的结构吻合。

### 2. 五组小红书参考形成了互补证据

- `xhs01_ai_2d_game` 展示了完整的横版资产思路：角色基准图、可分层的环境、远中近景、侧面行走、绿幕去背和序列帧导出。它证明横版副视角在现有“AI 视频 → 抽帧 → Godot”管线里技术上可行。
- `xhs03_milki_delivery` 最有参考价值的不是具体画风，而是横版旅途语言：角色持续向一个方向移动，风景、天气和目的地自然成为叙事的一部分。这与上学、送行、远行、抵达等成长剧情高度匹配。
- `xhs04_codex_godot_ep7` 说明横版宽画幅很容易建立天气、海岸、桥梁和远景气氛；但它的像素、暗色和平台游戏倾向不属于本项目的锁定美术，只能借构图与层次，不能借最终风格。
- `xhs02_godot_tilemap` 展示了俯视 / 斜俯视地形的模块化和自动补边思路，说明主视角更适合持续扩建村庄、学堂和不同区域。
- `xhs05_unity_godot_dev` 的俯视世界地图感适合路线概览、区域转换和地理交代，但画面信息量有限，不足以单独承担人物情绪段落。

所以这些参考并不是在要求项目二选一，而是在说明：**俯视适合建设可复用世界，横版适合提炼旅途与情绪。**

## 三、现有锁定美术如何与两种视角共存

### 1. 不改共同风格，只为不同相机重画几何

两个视角必须共享同一套“美术 DNA”：

- 温暖、生活化、可居住的手绘幻想乡村；
- 非像素、非写实、非 3D 渲染；
- 高明度、中低饱和，绿、土、木、蓝为基础色；
- 柔和白天光、短而淡的灰蓝 / 灰绿阴影；
- 轻东方而非强中式，允许泛幻想和少量西式乡村成分；
- 同一区域持续使用相同的建筑材料、屋顶色系、植物类型、纹理密度和元力点缀方式。

但“同风格”不等于“同一张资产直接旋转后复用”。相机改变后，形体信息也改变：

- 斜俯视房屋强调屋顶和正面；横版房屋需要完整立面、檐口侧边和明确地面接触线。
- 俯视树木以树冠占比和落地阴影为主；横版树木要有树干高度、枝叶侧面轮廓及前后景版本。
- 俯视桥梁按南北 / 东西方向出资产；横版桥梁要按侧立面、桥面遮挡和角色脚线单独制作。
- 俯视农田是平面模块；横版农田需要近中远三种高度或密度，以形成横向层次。

因此资产策略应是：**同一个物件拥有同一设计 ID，但有不同相机版本**，例如：

```text
house_village_01
├── top_oblique_south.png
├── top_oblique_east.png      # 确有剧情需要时再补
└── side_profile.png
```

共享的是设计、色板和材质，不共享错误的几何投影。

### 2. 当前两张批准图继续作为主视角硬基准

批准的地形图已经提供了道路、河流、农田、桥位和大面积可活动区域；批准的资产表提供了屋顶、墙体、木石材质、树木、井、风车、水车、桥和农场小物的统一语言。它们应继续定义俯视主视角，不能因增加横版而降级成“仅供参考”。

横版资产应从这些图中提取设计规则，而不是直接切下斜俯视物件使用：

- 蓝灰 / 暖橙屋顶、奶油墙、暖木构件保留；
- 圆润轮廓、清楚边缘和温柔笔触保留；
- 房屋等级需要按已锁定设定下调，开场村优先普通、略低档、单层或一层半民居，避免继续沿用现资产表中偏精致、偏两层的建筑体量；
- 横版背景不应突然变成小红书参考里的像素、强描边或现代欧美卡通风。

### 3. 角色是两种视角之间最重要的视觉桥梁

童年男女主 V1 设定板与场景在“柔和、手绘、蓝灰与米白”上能够共存，但它目前仍是角色方向 / 生产探索稿，不能直接缩小当游戏 Sprite：

- 面部和衣纹细节在俯视中远景会大量丢失；
- 男主肩包、发顶小束和补丁，女主双侧发饰、短披肩与蓝灰层叠，是应保留的中小尺寸识别点；
- 女主飘带、披肩、宽袖和男女主的层叠衣摆会增加骨骼穿插与侧面动作难度；
- 现板提供了正面、3/4 和背面等信息，但仍需要标准化的全身侧面，以及适配俯视舞台的正、背、左、右 Sprite。

建议为同一角色建立三层规格，而不是让一张图承担全部用途：

1. **角色基准设定**：锁脸、发型、服装结构、配色和年龄感；
2. **俯视游戏 Sprite**：4 方向起步，降低细节，强化轮廓与脚底落点；
3. **横版演出 Sprite**：标准全身侧面，左 / 右镜像为主，另做少量需要露正脸的 3/4 表演帧。

这样两个视角会因为“同一个角色设计”而统一，而不是因为强行复用同一张身体图而统一。

## 四、建议的使用场景切分

### 1. 默认用俯视主视角

以下内容应优先使用现有俯视 / 正交斜俯视系统：

- 村庄、学堂、县城、学院的首次空间介绍；
- 角色从家到学堂的具体路线和日常循环；
- 多人课堂、集合、测试、操场练习、集市和家庭劳动；
- 三人以上的对话、群像关系、谁靠近谁、谁离开谁；
- 元力作用于农田、水流、器具、阵法等需要同时看清“人—物—场地”关系的段落；
- 需要复用同一地点、只改变角色、时间、天气或事件的连续剧情；
- 城市 / 校园分区与区域路线概览。

主视角承担连续性。观众应能逐渐记住主角家、学堂、村口、河桥和农田的相对位置，这会把成长故事变成一个真正“住过”的世界。

### 2. 只有满足明确理由时才切横版副视角

横版建议用于：

- **线性旅途**：沿河、山路、田埂、城墙、校园长廊持续向一个方向走；
- **成长节点**：第一次正式上学、第一次离村、去县城、乘马车 / 飞行载具、最终升学远行；
- **两人同行**：并肩走、前后追赶、停在桥上或树下说话；
- **情绪留白**：黄昏独行、雨中回家、考试后沉默、离别后的长镜头；
- **环境展示**：望雷的雷云海、千湖的湖岸、云安的迷雾月岛等，需要让天空、地平线和区域气候成为主体的镜头；
- **特定横向表演**：递物、推车、骑行、奔跑、从门内走出等以侧面剪影最清楚的动作。

不建议横版用于：

- 仅仅因为“这一镜想换个感觉”；
- 多人频繁穿插、复杂前后站位的课堂或集市场面；
- 需要观众理解完整空间布局的地点初登场；
- 大量纵向移动、绕行、围观或阵法空间关系；
- 需要直接复用现有俯视房屋与地形资产的普通对白。

### 3. 建立稳定的切换语法

双视角最怕任意跳切。建议固定三种切法：

1. **建立 → 进入**：俯视全景交代地点和路线，角色走到出口或道路边缘；切到横版，表现沿途和情绪。
2. **旅途 → 抵达**：横版持续运动；经过桥、牌坊、校门等匹配物后，切回俯视，展示角色进入新地点后的空间关系。
3. **地图 → 记忆 / 情绪**：俯视现实场景中由声音、天气或某个物件触发，短暂进入横版段落；结束后回到同一俯视锚点。

横版段落最好有可识别的“开始锚点”和“结束锚点”，例如村口告示牌、桥、学堂门、马车站。这样切视角仍像同一个连续世界。

人物近景、半身对话框或立绘插入可以存在，但它们属于镜头尺度变化，不应被算作第三套世界视角，也不必另建完整场景管线。

## 五、横版副视角的具体美术与技术规范

### 1. 相机与空间

- 正交侧视，不做近大远小；角色在同一地面线上基本保持相同尺寸。
- 背景可用 3～4 层：天空 / 极远山与云、远景村落与树林、中景建筑与树、可交互地面与前景草木。
- 视差只用于建立缓慢层次，不能像 3D 镜头一样造成角色比例变化。
- 保持宽而清楚的表演带，前景植物不能长期遮住儿童角色的头、手和脚。
- 不引入平台跳跃式的高低台阶作为常规空间；本项目是成长叙事，不是平台游戏。

### 2. 光色与构图

- 默认仍是柔和白天光；黄昏、雨雾和夜色只作为有剧情含义的变体。
- 角色活动带的对比度应略高于远景，但不要用硬黑轮廓把人物贴在背景上。
- 远景降低饱和度和纹理密度即可，不使用真实透视缩小来制造深度。
- 横版宽画面可保留天空，但不要因此改成电影概念图或厚重风景插画。

### 3. 角色与动作管线

- 横版最低配置只需要侧面待机、走路、说话、回头 / 停步和一个通用手势；右向可由左向镜像，但肩包、发饰、衣襟等不对称元素必须有“镜像是否允许”的明确规则。
- 俯视主视角最低配置仍为正、背、左、右四方向；不能用横版侧面 Sprite 直接充当前 / 后向移动。
- `Idle / Blink / Talk / Nod` 等小幅循环可走骨骼或换图；转身、跑动、衣摆大幅摆动、拥抱、打斗和复杂交互继续走 AI 视频抽帧。
- 两种视角共享动作名称与时间规范，例如 `walk`, `talk`, `wave`，但各自拥有相机版本，避免在脚本层形成两套完全不同的事件系统。

## 六、主要风险与控制办法

| 风险 | 严重度 | 为什么会发生 | 控制办法 |
|---|---:|---|---|
| 角色跨视角不一致 | 高 | 当前角色稳定复用本就尚未验证；双视角新增全身侧面和另一套动作 | 先完成单一主角的 4 方向 + 侧面五姿态原型，未通过前不扩 NPC |
| 资产量失控 | 高 | 房屋、树、桥、道路等不能直接把斜俯视图旋转成侧视图 | 横版只做 3～5 个高复用“旅途场景包”，不为每个俯视地点做侧视副本 |
| 风格像两个游戏 | 高 | 小红书横版参考多为像素、强描边或西式卡通，与当前批准资产不同 | 只借镜头结构和生产方法；继续由批准图定义配色、材质、笔触和建筑语言 |
| 切换破坏空间连续性 | 中高 | 同一地点在两种投影下方位关系容易改变 | 使用桥、门、路牌等匹配锚点；横版不承担复杂地图解释 |
| 动作成本被低估 | 高 | 俯视要前后左右，横版还要更自然的侧面衣摆与脚步 | 把横版限制在少数英雄角色；背景 NPC 用简化循环或远景剪影 |
| 现有角色细节在游戏尺度下丢失 | 中高 | V1 设定板偏精致展示稿，缩小时脸和衣纹会糊 | 单独做游戏尺度重设计，以轮廓、发饰、肩包、披肩和色块识别为先 |
| 主视角规范被稀释 | 高 | 团队可能把“有两个视角”误解成所有资产角度都可混用 | 资产元数据必须标注 `camera_mode`；同一场景节点禁止混用错误投影资产 |
| 双视角变成无意义炫技 | 中 | 视频剪辑容易为了变化频繁切镜 | 剧本中每次切换必须填写功能：旅途、情绪、区域气候或侧面动作，至少命中一项 |

需要特别强调：**双视角不会自动降低成本。** 横版只在“受控使用”时划算。若要求每个村庄、教室、商店和城市都同时拥有完整俯视版与横版，成本会接近建设两套游戏，而不是多几个镜头。

## 七、推荐的落地顺序

### 阶段 0：先冻结术语

- `TOP_OBLIQUE`：现有主视角；俯视正交地面 + 固定斜俯视资产。
- `SIDE_STAGE`：横版副视角；正交侧视 + 有限视差层。
- `PORTRAIT`：对白 / 情绪近景；不是第三套世界视角。

明确术语能避免把“地面俯视”“资产斜俯视”“横版侧视”“角色 3/4 立绘”混成四种相机。

### 阶段 1：做一个最小双视角样片，不扩世界

只做同一段 20～30 秒的“从家走到村口”：

1. 俯视镜头：主角从家门沿道路走到村口；
2. 以村口告示牌或桥为锚点切换；
3. 横版镜头：主角沿田埂继续向学堂方向走，远景有农田、树和水面；
4. 再以学堂门切回俯视，进入多人场景。

这个样片只需要：一个定稿主角、一个普通乡村房、村口锚点、一个横版田埂场景包和两种基础走路。它能同时验证风格、比例、切换逻辑和生产成本。

### 阶段 2：设三道验收门

只有三项都通过，才把横版纳入正式剧本：

- **角色一致性**：不看对白也能确认两种视角是同一个人；发型、服装层次和识别点没有漂移。
- **世界一致性**：横版田埂、植物、房屋与批准俯视图像同一地区，而不是另一款游戏。
- **成本可控性**：该段可以在可接受时间内重复迭代；角色动作失败时有骨骼、换图或抽帧的明确替代路径。

### 阶段 3：横版只扩成少量“场景包”

第一阶段建议最多建设：

1. 东南村田埂 / 河岸；
2. 村到县城的山路 / 马车路；
3. 学堂或学院长廊；
4. 湖岸 / 码头；
5. 离乡远行的区域级风景。

每个场景包通过换天气、昼夜、前景植物和远景地标重复使用。不要按每一处俯视地图逐一制作横版镜像场景。

## 八、最终建议

项目后续应正式预留两种视角，但执行原则应写成：

> **俯视负责世界，横版负责旅途；俯视负责关系，横版负责情绪；俯视是常态，横版是有意义的强调。**

这套切分既保留了已批准地形图和资产表作为核心资产，也吸收了小红书横版参考中最值得借鉴的部分。它尤其适合「元力」从村庄日常、基础学堂一路走到远方高等学府的成长结构。

当前不应做的是马上批量生成两套场景。当前应做的是：先把童年主角变成真正稳定的生产角色，再用“家门—村口—上学路—学堂门”做一次最小双视角样片。样片通过后，把横版控制在少数高价值段落；未通过，则保留俯视主视角，并用立绘近景、天气、镜头裁切和环境微动画补足情绪，不会推翻现有路线。
