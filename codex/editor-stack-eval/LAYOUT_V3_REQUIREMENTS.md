# 导演台 Layout V3 需求与实现切片

状态：P0 实现依据

目标工程：`video_game/`（Godot 4.7.2，桌面与 Web 同一套运行时 UI）

布局依据：`layout-wireframe.png` 与 `USER_LAYOUT_V3.md`

## 1. 目标与决策

Layout V3 把导演台调整为桌面创作软件式工作区：场景对象统一从左侧 Hierarchy 选择，资源从左下资源库放入场景，属性统一在右侧 Inspector 编辑，章节与场景在底部 Project 管理，中间只保留画布和一条窄工具栏。

本轮继续使用全 Godot，不引入 JS 编辑器。现有 V2 的 `DirectorSceneModel`、`SceneRepository`、水域/角色/天气/内容控制器、UV 坐标、撤销与播放逻辑继续作为底层能力；Layout V3 主要重排信息架构，并增加一层统一的“元素引用与选择”模型。

## 2. 线框分区

从上到下、从左到右的固定区域如下：

| 线框区域 | V3 名称 | P0 内容 |
| --- | --- | --- |
| 最上方 | 菜单栏 | `文件`、`编辑`；文件菜单可新建章节、场景和元素，编辑菜单提供撤销、重做、保存 |
| 左上 | 元素列表 / Hierarchy | 当前场景所有元素；无场景时显示“请先打开场景” |
| 左下 | 资源列表 | `默认资源 / 自定义资源`；分类为背景图、树木、角色、房屋；支持点击放置或上传 |
| 左侧与画布之间 | 工具条 | 选择/移动、缩放、旋转、镜像；P0 先让选择/移动与镜像可用，缩放复用属性值，旋转若数据契约未完成则灰显并注明“后续开放” |
| 中央 | 主编辑区 | Godot 场景画布；显示选择轮廓、路线、水域和区域控制点；播放时锁定编辑 |
| 右侧 | 属性区 / Inspector | 根据当前元素类型显示属性；不再要求用户先理解“功能页签” |
| 最下方 | Project | 左侧章节树，右侧显示所选章节内的场景卡片；可在此新建章节/场景和打开场景 |

桌面基准尺寸为 1280×720。P0 优先桌面鼠标键盘；窄屏保持面板可见和可滚动，不承诺手机精细编辑。

## 3. “一切皆元素”统一模型

### 3.1 定义

“一切皆元素”首先是编辑器选择模型，不要求立即把所有数据迁移到一个扁平数组。Hierarchy 将当前场景下列对象统一展示成可选元素：

- 背景图：单例，映射 `model.background`。
- 普通元素：房屋、树木、道具等，映射 `model.elements[]`。
- 角色：映射 `model.actors[]`。
- 水流区域：每个范围映射 `model.water_regions[]`。
- 底图裁片区域：映射 `model.background_regions[]`，同时作为背景的子项显示。
- 特效：P0 将当前天气作为一个“天气/下雨”元素；雾气与未来特效只预留类型和入口，不放置不可用假按钮。

统一元素引用采用编辑器内存结构：

```text
{ kind, id, parent_id?, label }
```

`kind` 至少包含 `background`、`element`、`actor`、`water`、`background_region`、`weather`。选择引用不写入场景文件；实际属性仍回写现有对应字段。这能保持 V2 场景完全兼容，也避免一次大迁移破坏已有作品。

### 3.2 选择与高亮

- 点击 Hierarchy 行后设置唯一当前选择，主编辑区显示该对象的现有 gizmo 或选择轮廓，Inspector 刷新为对应属性。
- 点击画布对象反向选中 Hierarchy 行。
- 选中背景时主编辑区以画布边界表示选择；Inspector 同时列出其下所有底图裁片区域，点击区域名可切换到该区域。
- 选中角色时仅显示该角色路线；选中水流或底图区域时显示范围轮廓和控制点。
- 删除对象后选择回退到背景；切换场景后清空旧引用并默认选中背景。

## 4. 资源列表

### 4.1 默认资源

默认资源分四类：

- 背景图：村庄预设、空白背景。
- 树木：现有 `art/sliced/` 中的树木。
- 角色：现有角色注册表中的农夫与蓝衣农夫。
- 房屋：现有 `art/sliced/` 中的房屋。

点击普通资源后进入待放置状态，再点击画布创建；现有 Godot 拖放能力可保留。角色资源创建角色实例并等待设置出生点/路线。背景资源不进入待放置状态，而是执行替换流程；只要当前场景已有背景，就必须弹出“当前场景已有背景，是否替换？”确认框。

### 4.2 自定义资源

P0 支持上传 PNG/JPEG/WebP：

- 自定义背景：复用现有背景上传、2048 px 限制和场景目录持久化。
- 自定义普通图片：上传后复制到 `user://director_desk/assets/`，生成稳定 `asset_id` 和元数据，显示在“自定义资源”页；点击后可作为 bottom-center 锚点元素放置。
- P0 自定义图片先按静态透明贴图处理；人物序列帧切片规则、动画帧率和碰撞属于后续项。
- 上传失败、格式不支持或超限必须显示中文错误，不创建半成品记录。

自定义资产索引与场景 schema 分开保存；场景元素只引用稳定 `asset_id`。缺失资源时保留元素数据并显示占位/警告，不能静默删除。

## 5. Inspector 属性规则

所有可渲染对象至少显示名称、类型与整数图层。不同类型扩展如下：

| 类型 | P0 属性 |
| --- | --- |
| 背景 | 来源、尺寸、替换背景、内置道具显隐、底图裁片区域列表 |
| 房屋/树木/普通图片 | 图层、位置、缩放、镜像、删除；路线能力入口 |
| 角色 | 角色类型、图层、出生点；添加/编辑路线、速度、显示、循环、碰撞方式、删除 |
| 水流区域 | 图层、范围形状、流向、流速、碰撞、删除；允许场景中存在多个范围 |
| 底图裁片区域 | 图层、范围控制点、删除 |
| 天气/特效 | 类型、启用、强度；P0 实现下雨，雾气只保留后续数据方向，不伪装成已实现功能 |

用户要求“人物或者树木等可有路线”。P0 保证角色路线完全可用；普通元素先显示路线区和“后续开放”说明，不在没有播放控制器的情况下保存无效路线字段。后续若让树木或图片沿路线移动，应抽出通用 `motion` 组件并兼容角色现有 route，而不是复制一套路径实现。

用户要求区域类可有多个范围。当前水域数组和底图裁片数组已经满足多实例；P0 在 Hierarchy 中逐个列出并可选择。未来雾气等效果采用“一个特效元素包含多个区域”或“每个区域一个元素”需要在实现真实雾气时再冻结，当前不改 schema。

## 6. Project 章节/场景区

底栏采用类似 Project 的双栏布局：

- 左侧为章节树，展示所有章节并支持选择、新建和章节操作。
- 右侧为当前章节内容区，以卡片或列表显示场景；双击或按钮打开场景。
- 新建场景默认归入当前 Project 章节，必须延续现有 chapter fix 行为。
- 场景和章节的重命名、排序、删除仍复用 V2 repository 与确认流程。
- P0 播放范围仍为当前场景，章节不自动连播。

## 7. 菜单与工具

### 7.1 菜单栏

`文件`菜单：新建章节、新建场景、新建角色、新建水流区域、新建底图裁片区域、上传自定义资源、立即保存。对象类命令与 Hierarchy 的“+”菜单使用同一组 action，不维护两套逻辑。

`编辑`菜单：撤销、重做、删除所选元素；不可用项灰显。所有菜单项使用中文。

### 7.2 工具条

- 选择/移动：P0 可用，复用现有画布命中与拖动。
- 缩放：P0 通过 Inspector 数值编辑普通元素缩放；工具按钮选中时给出提示，不承诺拖拽缩放手柄。
- 旋转：P0 灰显并标注“后续开放”，因为现有 schema 和控制器均无旋转字段。
- 镜像：P0 对普通元素提供水平镜像并持久化；角色镜像由行走方向/动画系统处理时再统一，不直接破坏现有占位角色。

## 8. 数据模型变化与兼容

P0 尽量不改“统一元素数组”，而做以下最小兼容扩展：

1. 普通 `elements[]` 增加可选 `flip_h: bool`，缺失时默认 `false`，未知字段 round-trip 规则继续成立。
2. 自定义素材以稳定 `asset_id` 注册，普通元素仍使用现有 `asset_id` 字段；渲染层从内置 `res://` 查找扩展为“内置注册表或用户资产注册表”。
3. 水域增加/保留 `layer` 属性；旧数据缺失时使用当前安全默认层级。
4. Hierarchy 选择、面板展开、当前工具等纯编辑器状态不写入场景 JSON。

任何扩展都必须满足旧 V2 场景可打开、保存后未知字段不丢、现有 selftest 继续通过。

## 9. P0 验收

1. 1280×720 下能看到菜单栏、Hierarchy、资源库、工具条、主画布、Inspector 和底部 Project 七个区域，不能互相遮挡。
2. 无场景时 Hierarchy 显示明确空状态；打开场景后至少列出背景、普通元素、角色、水流、底图区域和天气。
3. Hierarchy 与画布选择双向同步，选择角色/水流/底图区域时现有 gizmo 正确显示。
4. 默认资源有背景图、树木、角色、房屋四类；点击树木/房屋可放置，点击角色可创建，背景替换必须确认。
5. 自定义页可上传至少一类持久化图片资源并再次放置；错误有中文提示。
6. Inspector 随选择类型变化，至少可修改已有 V2 能力中的层级、缩放、路线速度/显隐和水流参数。
7. Project 左章节、右场景；从当前章节新建场景后归属正确。
8. 文件/编辑菜单和 Hierarchy/Project 快捷入口调用相同动作。
9. 移动与镜像可用；旋转等未实现工具清晰灰显，不出现假功能。
10. `godot --headless --path . --import --quit` 和 `godot --headless --path . -- --selftest` 通过，并增加 Layout V3 结构、Hierarchy 和兼容字段的自测。
