# Layout V3 工具栏问题答复

以下说明以当前 `main` 已合并的 Layout V3 代码为准，主要依据 `video_game/scripts/director/director_desk.gd` 中的工具栏绑定、模式枚举和画布操作。

## 1. “套索”与“水域”分别做什么？为什么点击套索后还是水域？

当前工具栏中的这两个按钮其实是**两种创建水域的方式**，不是“水域工具”和“通用套索工具”的区别：

- **水域**按钮进入 `BOX_WATER` 模式。它用于在画布上拖出一个矩形水域。创建以后，矩形可以移动、拖四角调整大小，并可设置流向、流速、图层和碰撞。
- **套索**按钮进入 `LASSO_WATER` 模式。它用于逐点勾画一个多边形水域，适合弯河、不规则水面。双击、点回起点或按 Enter 后闭合，并生成一块 `shape = polygon` 的水域。

所以，点击“套索”以后得到的仍然是水域，这是当前实现的正常行为，不是操作错误。工具栏里的“套索”实际是“**套索水域**”的简称，名称确实容易让人误以为它是 Photoshop 或 Unity 那种通用区域选择工具。

如果想圈出一块背景并单独设置显示层级，应使用旁边的 **“裁片”** 工具。它进入 `LASSO_REGION` 模式，闭环后创建的是“底图裁片区域”，而不是水域。当前三者的实际对应关系是：

| 工具栏按钮 | 内部模式 | 创建结果 |
| --- | --- | --- |
| 水域 | `BOX_WATER` | 矩形水域 |
| 套索 | `LASSO_WATER` | 多边形/不规则水域 |
| 裁片 | `LASSO_REGION` | 可单独设置图层的底图区域 |

右侧水域属性中出现的“矩形框选”和“套索 / 多边形”也是同一组能力的两个入口。

## 2. 为什么套索闭环后自动回到“移动”？

这是当前代码明确设定的行为。套索闭环并创建元素后，`_finish_lasso()` 会主动执行 `_set_mode(Mode.SELECT)`；界面上的 `SELECT` 模式显示为“移动”，因此高亮会回到“移动”。

这样设计的目的，是把套索当作一次性创建动作：完成一块区域后立即回到选择/移动，避免用户下一次点击时无意中又开始创建另一块多边形。创建出的水域或底图裁片仍然会保持选中，并在画布和 Inspector 中显示其属性。

这不是闭环失败，也不是工具状态丢失。不过，目前矩形“水域”工具创建完后仍留在矩形水域模式，而套索创建完会回到移动，两者行为并不完全一致。因此用户感觉跳转突然是合理的；若后续优化，最好统一成“工具保持”或“一次创建后回到移动”，或者提供一个“连续创建”开关。

## 3. 缩放工具应该怎么用？为什么点击后没有选中状态、也没有反应？

当前需要分开看“缩放能力”和“工具栏缩放按钮”：

- **普通元素的缩放能力已经实现。** 先在 Hierarchy 或画布中选中树木、房屋或自定义静态图片，然后在右侧 Inspector 的“缩放”滑杆中调整，范围目前是 `0.1～2.0`。
- **工具栏里的“缩放”操作手柄没有实现。** 这个按钮没有对应的 `Mode`，也没有写入 `_mode_btns`，点击时只会在状态栏显示“请在属性面板调整元素缩放”。它不会进入选中状态，也不会让画布出现缩放控制点。

因此，如果期待“点缩放 → 选中工具 → 在画布拖拽缩放”，那部分目前确实尚未实现，不是用法不对。更准确地说，当前属于“**缩放属性已实现，但工具栏缩放模式只是提示入口**”。

现阶段正确用法是：

1. 先选择一个普通图片元素，例如树木、房屋或上传的静态图片。
2. 在右侧 Inspector 找到“缩放”滑杆。
3. 拖动滑杆调整大小。

角色、背景、水域和底图裁片目前不使用这个普通元素缩放滑杆：水域矩形通过四角控制点调整范围，多边形水域和底图裁片通过顶点调整；背景没有通用缩放属性；角色也尚未暴露缩放字段。

工具栏按钮没有选中反馈，确实容易被理解成故障。若继续迭代，应当二选一：要么实现真正的画布缩放 gizmo 和独立模式，要么在实现前把按钮灰显并直接写成“缩放（在属性中）”，避免把提示按钮伪装成可操作工具。

## 4. 为什么旋转是灰色、不能点击？

旋转目前是**明确未实现并主动禁用**的能力。代码创建“旋转”按钮后直接设置了 `disabled = true`，提示文字为“后续开放”，回调本身也没有执行任何操作。

这不只是缺少一个按钮事件：当前场景 schema 的普通元素没有 `rotation` 字段，`SceneContentController` 渲染元素时也没有应用旋转，画布没有旋转 gizmo，Inspector、撤销和自测同样没有对应能力。因此现在保持灰色是为了避免产生“按钮能点但数据不会保存”的假功能。

要让旋转真正可用，至少需要一起补齐：元素 `rotation` 数据及向后兼容、渲染应用、Inspector 数值编辑、画布旋转手柄、撤销/重做、保存恢复和自测。在这些完成之前，灰色不可点是当前 P0 的预期状态。

## 简要结论

当前工具栏里，“移动”“矩形水域”“套索水域”“裁片”和“角色路线”是真正的编辑模式；“镜像”是对当前普通元素立即执行一次操作；“缩放”只有 Inspector 属性可用，工具栏按钮尚不是编辑模式；“旋转”则完全未实现并被主动禁用。用户对“套索”“缩放”产生疑惑，主要原因是按钮名称和视觉状态没有准确表达当前实现边界，并非用户操作错误。
